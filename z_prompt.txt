━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. FIRST: AUDIT BEFORE CHANGING
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Do NOT blindly modify CSS.

First inspect the COMPLETE application and identify:

* Text that is too tightly packed
* Text with insufficient line-height
* Paragraphs that look cramped
* Headings that wrap awkwardly
* Cards with too much empty space
* Cards with too little space
* Sections that are vertically unbalanced
* Excessive blank areas
* Uneven margins
* Uneven padding
* Inconsistent gaps
* Misaligned icons
* Misaligned buttons
* Unequal card heights
* Broken grids
* Content that feels compressed
* Content that feels unnecessarily stretched
* Elements that are too close together
* Elements that are too far apart
* Poor visual hierarchy
* Mobile overflow
* Tablet layout problems
* Desktop layout problems
* Elements that become awkward at intermediate widths

Then fix these issues systematically.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. TEXT MUST BREATHE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

One of the current problems is text appearing too close together.

Fix typography globally.

Pay special attention to:

* line-height
* letter-spacing
* paragraph width
* heading margins
* label spacing
* text-to-icon spacing
* text-to-button spacing
* text-to-card-edge spacing

DO NOT make text unnecessarily large.

Instead, give it proper breathing room.

For normal body text:

line-height should generally be around 1.5–1.7.

For headings:

line-height should generally be around 1.1–1.3.

For compact metadata:

use a smaller but still readable line-height.

Avoid:

line-height: 1;

for normal paragraphs.

Avoid extremely tight letter-spacing.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. CONTROL TEXT WIDTH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Do not allow long paragraphs to span the entire screen.

Use reasonable max-widths.

For readable descriptive text:

approximately 55–75 characters per line where practical.

For hero descriptions:

use a controlled max-width.

Example concept:

max-width: 650px;

Do not force every paragraph to use the same width.

Short text can remain compact.

Long explanatory text should wrap naturally.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. FIX EMPTY SPACE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IMPORTANT:

Do NOT remove all whitespace.

Whitespace is necessary.

The problem is UNINTENTIONAL whitespace.

Inspect every page and section.

If a section has:

Huge empty vertical space
+
Very little content

reduce the section padding/min-height.

If a section contains important content that feels cramped:

increase spacing.

Use visual balance instead of fixed giant heights.

Avoid unnecessary:

min-height: 100vh;

for small content sections.

Avoid oversized padding such as:

padding: 120px;

unless there is a strong design reason.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. BALANCE EVERY SECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every section should visually answer:

Is the content centered correctly?

Does the section have enough breathing room?

Is the content too high or too low?

Is there excessive unused space?

Are elements grouped logically?

Use proximity principles:

Related elements should be closer together.

Unrelated elements should have more separation.

For example:

Heading
↓ small gap
Description
↓ medium gap
Primary action

NOT:

Heading

```
    huge gap
```

Description

```
    huge gap
```

Button

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. CARD BALANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Audit every card.

Cards should not have:

* giant empty bottoms
* cramped text
* inconsistent padding
* random heights
* misaligned buttons
* floating icons
* excessive internal whitespace

Use consistent internal spacing.

Example structure:

↓

↓

↓

↓

Maintain visual rhythm.

If cards are in the same grid, make their heights visually consistent where appropriate.

Do NOT force equal heights when doing so creates excessive empty space.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. GRID BALANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Inspect every grid.

Do not blindly use:

for every screen.

Choose the number of columns based on:

* viewport width
* content width
* card minimum width
* readability

Example behavior:

3 columns

Tablet:
2 columns

1 column

But use content-aware breakpoints rather than blindly following these numbers.

Cards should never become unnaturally narrow.

* badges

* statistics

21. DO NOT OVER-CORRECT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Do NOT solve cramped UI by adding huge padding everywhere.

Do NOT solve empty space by removing all padding.

Do NOT solve wrapping by making everything tiny.

Do NOT solve overflow by hiding content.

Do NOT solve mobile problems with:

unless the overflow is genuinely intentional.

Fix the ROOT CAUSE.
